## Repository Overview

Terraform module `infrahouse/tcp-pod/aws`: runs a TCP service in an EC2 autoscaling group behind a Network Load
Balancer, with Route53 alias records pointing at the NLB. Supported AWS provider versions: `>= 6.0, < 7.0`.

## Commands

```bash
make bootstrap      # Install Python deps (run inside a virtualenv) and git hooks
make fmt            # terraform fmt -recursive + black tests
make lint           # Check formatting: black --check tests, terraform fmt -check
make test           # Full pytest suite - creates REAL AWS infrastructure
make test-keep      # One test case, keeps AWS resources for debugging
make test-clean     # One test case, destroys resources (run before PRs)
make clean          # Remove .pytest_cache and .terraform directories
```

Run a single test case (parametrize ids combine as `<provider>-<subnets>-<scheme>`):

```bash
pytest -xvvs \
    --aws-region=us-west-2 \
    --test-role-arn=arn:aws:iam::303467602807:role/tcp-pod-tester \
    -k "aws-6-subnet_public_ids-internet-facing" \
    tests/test_tcp-pod.py
```

Add `--keep-after` to keep the infrastructure after the test.

## Testing

- Tests are integration tests: they create real AWS resources (default region `us-west-2`) via `terraform_apply`
  from pytest-infrahouse, then validate with boto3 clients. A full run takes a long time (timeout is 1 hour per test).
- The one test, `tests/test_tcp-pod.py::test_module`, is parametrized over the AWS provider version
  (`aws-6`) and LB subnet placement (`subnet_public_ids` → `internet-facing`, `subnet_private_ids` →
  `internal`).
- The test root module lives in `test_data/tcp-pod`. It deploys a jumphost pod (SSH on port 22 through the NLB) and
  the internet-facing case actually SSHes through the NLB. The test rewrites `test_data/tcp-pod/terraform.tf` and
  `terraform.tfvars` at runtime, so local changes to those two files are throwaway.

## Architecture

- **Dual-provider design**: the module takes `aws` plus an `aws.dns` alias (declared in `terraform.tf`) so Route53
  records can live in a different AWS account. Any Route53 resource/data source must use `provider = aws.dns`
  (see `dns.tf`, `datasources.tf`). Callers who don't split accounts pass the same provider for both.
- **NLB scheme is inferred, not configured**: `lb.tf` sets `internal` based on `map_public_ip_on_launch` of the
  first subnet in `var.subnets` — public subnets produce an internet-facing NLB, private subnets an internal one.
- **Derived defaults** live in `locals.tf`: ASG min size defaults to the number of backend subnets (max size = +1),
  `dns_a_records` defaults to `[var.service_name]`, and the NLB name prefix is the first 6 chars of the service name.
- **Files are split by function**: `asg.tf` (ASG, launch template, lifecycle hooks), `lb.tf` (NLB, listener, target
  group), `dns.tf`, `security_group_backend.tf` / `security_group_nlb.tf`, `autoscaling.tf` (CPU target tracking),
  `cloudwatch.tf` (CPU alarm), `iam.tf` (instance profile via the `infrahouse/instance-profile/aws` child module),
  `ssh.tf` (fallback generated key pair).
- **Tagging drives instance refresh**: `locals.tf` builds `default_module_tags` (including Vanta compliance tags);
  the ASG propagates them at launch and its rolling `instance_refresh` is triggered by tag changes.
- **ECS support**: `attach_target_group_to_asg = false` plus `target_group_type` exist so ECS can register targets
  itself; don't assume the target group is always attached to the ASG.

## Repo conventions

- The README's Requirements/Inputs/Outputs tables are auto-generated by terraform-docs — the pre-commit hook
  regenerates and stages `README.md`. Don't hand-edit those tables; edit variable/output descriptions instead.
- Commit messages follow Conventional Commits, enforced by `hooks/commit-msg`; the changelog is generated by
  git-cliff (`cliff.toml`).
- Several files are managed centrally by the `infrahouse/github-control` repository and must not be edited here:
  `.claude/CODING_STANDARD.md`, `hooks/*`, `.terraform-docs.yml`, `mkdocs.yml`, `cliff.toml`, and most
  `.github/workflows/*`. Propose changes via a PR to github-control instead.
- `.claude/TERRAFORM_MODULE_REQUIREMENTS.md` defines repo-wide requirements (README badges/sections, docs/ pages
  for GitHub Pages, release process). Project commands: `/review-local` (local module review) and
  `/generate-excalidraw` (architecture diagram).
